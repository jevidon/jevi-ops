## Decisions and deviations from the plan

- `captured_at` is generated by the client alongside the ids (not by the server action) so that a retried save carries an identical envelope; the harness caught that a regenerated timestamp changed the digest and produced `operation_id_reused`.
- Plugin configuration uses `config.json` instead of TOML (the interactive Hermes Python may predate `tomllib`).
- Ingest captures are recorded with `processing_state = queued` (previously they were invisible rows); they now appear in Inbox › Captures.
- `lib/command-error.ts` (`CommandError`) and `apps/web/src/lib/client-id.ts` are small utilities that existed only in the scrapped PRs; they are carried here because the capture code needs them.
- The `integrationFetch` half-duplex fix made on the old branch does not apply: `main`'s STT client uses the OpenAI SDK's own fetch, which handles streamed bodies.

## Known limitations (accepted for Gate B)

- No automatic consumer: a capture the browser abandons before the interpret call stays `queued`; Hermes `/capture` never interprets.
- The bridge is conservative, not replay-safe: `execution_uncertain` and `partial_execution` need Gate C reconciliation; `create_calendar_event` from capture goes to review.
- The browser holds the recording only in memory; `upload_incomplete` offers "Retry upload" while the tab is open and nothing more.
- Loopback is trusted by policy. A loopback proxy that forwards to a cloud model (Hermes's own `127.0.0.1:8080` does exactly that) is indistinguishable from a local model; the allowlist protects against misconfiguration, not against a deliberately configured local proxy.
- Legacy `/api/capture/voice*` and `/api/ingest/capture` remain synchronous and unpoliced until Gate C reroutes them; the Capture Portal no longer uses them.
- `/uploads/*` remains public; the global error handler still returns `err.message`; `PRIVATE_SOURCES_DIR` bypasses `EnvSchema`.
- `capture_client` device binding is advisory.

## Integration dependencies for Gate C

`capture_receipts.processing_state = queued` is the backlog; `capture_attempts` is the fencing model to replace with `capture_jobs`; `capture_async_enabled` flips ownership (the bridge answers `409 capture_async_owned`); `retryPermitted()` in `lib/capture/service.ts` defines what a retry may touch; `EXTERNAL_ACTIONS` in `legacy-bridge.ts` lists effects that need their own reconciliation model.

## Rollback / recovery

Non-destructive by design: revert or unregister `captureBridgeRoutes` to stop interpretation; the Capture Portal falls back to legacy `voice-actions.ts` functions (untouched); revoke `capture_client` tokens to stop writes; keep the four new tables and `CAPTURE_MEDIA_DIR` (they are the replay protection and the only index to stored media); disable the plugin by removing it from `plugins.enabled`, leaving `~/.hermes/jevi-capture/pending` for inspection. No rollback step deletes a stored capture.
